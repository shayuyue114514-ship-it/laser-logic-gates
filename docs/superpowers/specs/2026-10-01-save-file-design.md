# 存档（打开与保存）设计

日期：2026-10-01
项目：激光逻辑门运算
状态：已确认，待实现

## 1. 背景与目标

目前电路只活在内存里，关掉页面就没了。本设计为「文件」按钮下方的弹窗加上打开与保存能力，让电路能落到磁盘上、能被重新读回来、也能发给别人。

用户已确认的两个前提：

- 存档的定位是**导出与导入文件**，不是浏览器本地的单档自动续玩。
- 存档文件里装**电路加视野**，不装界面设置与配色。

## 2. 范围

### 做

- 把当前电路与视野存成一个 JSON 文件。
- 从 JSON 文件读回电路与视野，并彻底替换当前画布内容。
- 在浏览器支持时，用文件系统访问 API 写回同一个文件，做到真正的「保存」而非每次「另存一份」。
- 在不支持该 API 的浏览器上优雅降级，功能变少但不报错。

### 不做

- 未保存改动的提醒。
- 自动保存。
- 最近打开列表。
- 跨刷新记住文件句柄（句柄只存在内存里）。
- 快捷键。
- 存档内嵌界面设置与配色。

## 3. 存档格式

JSON 文本，UTF-8，后缀 `.json`。

```json
{
  "format": "laser-gate",
  "version": 1,
  "view": { "worldX": 0, "worldY": 0, "screenX": 480, "screenY": 300, "scale": 1 },
  "elements": [
    { "type": "deflector", "gx": 2, "gy": -1, "dir": 1, "on": false },
    { "type": "light", "gx": -3, "gy": 0, "dir": 0, "on": true }
  ]
}
```

字段说明：

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| `format` | 格式标记 | 固定为 `laser-gate`，用来挡住误读别的 JSON |
| `version` | 结构版本 | 整数，当前为 `1`，结构变更时递增 |
| `view.worldX` / `view.worldY` | 相机参考点的世界坐标 | 与 `screenX` / `screenY` 共同确定视野 |
| `view.screenX` / `view.screenY` | 相机参考点的屏幕坐标（CSS 像素） | 与上面两项共同确定视野 |
| `view.scale` | 缩放倍率 | 非对数形式，读档时取对数写入内部状态 |
| `elements[].type` | 元件类型标识 | 与元件类型表中的标识一致 |
| `elements[].gx` / `elements[].gy` | 元件所在格的整数索引 | 世界坐标为 `gx + 0.5` / `gy + 0.5` |
| `elements[].dir` | 朝向 | 0 上、1 右、2 下、3 左 |
| `elements[].on` | 光源开关 | 非光源元件恒为 `false` |

### 三个刻意的决定

**位置存整数格索引，不存世界坐标浮点数。** 元件永远坐在格心上，世界坐标必定是半整数，存索引既无损又不会累积浮点误差。

**朝向存离散索引，不存旋转动画的连续角度。** 读档时角度直接落到位，不播旋转动画。

**瞬态一律不存。** 激光场、微帧计数、累加器、上一微帧的发射记录、阻挡图、虚影位置与动画进度、悬停与按下状态、正在删除中的元件，全都不进存档。读档后这些从零重新推演。

## 4. 模块划分

按项目现有的「初始化、更新渲染、输入、重置」分离约定拆成四块，每块只干一件事，彼此通过明确的数据接口通信。

### 4.1 序列化

输入是当前元件数组与相机状态，输出是纯数据对象。不碰 DOM，不碰画布，因此可以独立验证。

序列化时过滤掉正在删除动画中的元件，它们不应进入存档。

### 4.2 反序列化

输入是解析后的纯数据对象，输出是「可加载的元件列表 + 相机状态」，或者一个失败原因。

所有校验集中在这一层，坏数据在这里被挡住，不往下传。校验项见第 6 节。

### 4.3 文件读写

把两条 API 路线包在一起，对外只暴露三个动作：打开、保存、另存为。上层不需要知道当前浏览器走的哪条路线，也不需要处理能力检测。

### 4.4 弹窗界面

复用已有的弹窗初始化与逐帧同步机制。文件弹窗的显示、隐藏、位置、透明度全部由已有的机制驱动，不另起一套动画状态。

## 5. 数据流

**保存：** 元件数组与相机状态 → 序列化 → 纯数据对象 → JSON 文本 → 写文件。

**打开：** 文件 → 文本 → JSON 解析 → 校验 → 反序列化 → 应用状态 → 彻底清理 → 标记重绘。

**清理顺序不能乱。** 清理必须放在「应用状态」之后。阻挡图是按元件下标建立的行列缓存，替换元件数组会让它整体失效；如果在替换之前就作废，重建可能发生在数组处于半替换状态的中途，算出一份与新数组对不上的图。所以顺序是：先替换元件数组，再作废阻挡图。

清理包含：删除全部元件图形节点并清空元件数组、清空接收掩码、清空激光场、清空上一微帧发射记录、微帧计数与累加器归零、阻挡图整体作废、虚影与悬停按下状态复位、相机当前值与目标值一起设为存档中的视野。

相机**当前值与目标值都要设**。只设目标值的话，读档后相机会从旧位置慢慢飘过去，而不是立刻到位。

## 6. 错误处理与降级

外部文件是系统边界，必须校验。逐条校验，坏条目跳过并计数，不整体拒绝加载。

| 情况 | 处理 |
| --- | --- |
| 用户取消系统对话框 | 静默返回，不提示 |
| 文件不是合法 JSON | 提示「这不是本程序的存档」 |
| `format` 标记不匹配 | 同上 |
| `version` 不认识 | 同上 |
| 某条元件的类型标识无法识别 | 跳过该条，计数 |
| 某条元件的坐标不是整数 | 跳过该条，计数 |
| 读取结束后有跳过条目 | 提示跳过了几条 |
| 写入失败 | 提示写入失败 |
| 浏览器不支持文件系统访问 API | 降级，见下 |

### 降级方案

能力检测用 `"showSaveFilePicker" in window`。

不支持时：保存退化为下载（Blob 加带 `download` 属性的链接），另存为隐藏，打开退化为普通文件选择框。功能少一点，但不报错。

降级模式下文件名取当前文件名；未打开过任何文件时用默认名，不弹命名对话框。

### API 支持现状

`showSaveFilePicker()` 要求安全上下文，且必须在用户点击这类交互中调用，否则抛安全错误。支持情况：Chrome 86 起、Edge 86 起、Opera 72 起；Firefox 与 Safari 不支持。

文件句柄拿到后，写回同一个文件用文件句柄的 `createWritable()`。

## 7. 界面形态

文件弹窗从当前的一行占位改为四行：

1. 当前文件名，未打开过文件时显示「未命名」。
2. 打开。
3. 保存。
4. 另存为。

后三行各放一个按钮，占满整行宽度，文字居中。

**选竖排而不是三个按钮横排**，是因为面板内宽只有 224 像素，三个按钮横排每个只剩 70 像素左右，「另存为」加省略号会被挤到换行。

在降级模式下隐藏「另存为」，其余三行保持。

## 8. 验证方式

手工验证，逐项确认：

1. 放几个元件、转几个朝向、开一个光源，保存成文件。
2. 用文本编辑器打开该文件，肉眼核对元件数量与坐标。
3. 清空画布，再打开这个文件，比对元件是否原样回来。
4. 确认视角是立刻到位，而不是飘过去。
5. 手工把一个坐标改成非法值，确认读档时跳过并提示，而不是整个崩掉。
6. 改一个元件的类型标识为不存在的值，确认同上。
7. 把文件内容改成一段普通 JSON，确认提示「这不是本程序的存档」。
8. 在系统对话框里点取消，确认无提示、无异常。
9. 第二次点保存，确认不再弹对话框而是直接覆盖同一个文件。
