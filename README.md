# 激光门

在网格上放置光学元件，激光沿网格横平竖直地传播，被元件偏转、截断或透射，而元件的发射与停止又由它收到的光决定。把光源、偏转器与反相器接起来，与门、或门、非门都能亲手搭出来：光路怎么走，结果就是怎么算出来的。

- 在线试玩：<https://laser.shayuyue.com>
- 源码仓库：<https://github.com/shayuyue114514-ship-it/laser-logic-gates>

整个项目是纯前端，没有后端、没有数据库、没有账号。所有结算都在浏览器里跑，电路以文件形式存在你自己的磁盘上，服务器只负责把页面发出去。

## 玩法规则

这套引擎的规格写在 [基本逻辑.md](基本逻辑.md) 里，包括网格与坐标的定义、元件与激光的模型、发射与阻挡的判定、接收的两种方式，以及每微帧的结算流程。读代码之前先读它，各部分的实现都对着它写。

其中有三条决定了一切。一个格子最多放一个元件，元件中心落在格心点上。激光是无向的横平竖直线段，从发射者的中心出发，止于第一个阻挡它的元件中心，没有阻挡者就延伸到无穷远，多条激光重合时完全合并、效果不叠加。所有元件都有 1 微帧的延迟：第 t 微帧收到光，第 t+1 微帧才响应并输出。

## 五种元件

| 元件  | 形状               | 行为                       |
| --- | ---------------- | ------------------------ |
| 光源  | 带尖头的方块，形如箭头      | 开启时朝箭头方向发出激光             |
| 偏转器 | 实心三角形            | 任意方向入射的激光都被它截住，再朝箭头方向发出  |
| 透射器 | 三角形，底边向内凹        | 偏转方式与偏转器相同，但入射激光会继续向前穿过它 |
| 反相器 | 三角形加顶点上的气泡，即非门符号 | 没收到激光时朝箭头方向发射，一旦收到就停止    |
| 灯   | 圆角方块             | 被激光照到时亮起，只作指示，不发射        |

阻挡属性按水平与垂直两个全局轴分别记录，并随元件旋转而旋转。偏转器、光源、反相器、灯两个轴都挡，透射器两个轴都不挡。

## 两个页面

首页是封面与分流处。整页只有一张画布，中间竖排着标题、域名与四个入口，两侧各跑一小段演示电路，用的是编辑器那一套结算引擎，所以首页看不到任何与编辑器不一致的激光行为。四个入口是新建、打开、教程、关于。

编辑器是真正搭电路的地方：上方是元件面板，左侧是存档列表，中间是网格视口，右下是读数面板，默认收起。面板上除了一个选中槽和五个元件槽，还有教程、文件、设置三个按钮，它们与元件槽共用同一套悬停与按下的动画状态。

## 存档

存档文件的后缀是 `.lccas`，内容是一段 JSON，顶层四个字段：`format` 固定为 `laser-gate`，`version` 当前为 1，`view` 记视野（参考点的世界坐标与屏幕坐标，加上缩放），`elements` 是一组元件记录，每条只记类型、格索引、朝向与开关。界面设置与配色属于工作环境偏好，不进存档。

读档先整份校验：格式标记不对或版本不认识就整体拒绝；个别坏条目则跳过并报出跳过了几条。校验通过之前不会动画面，所以读一份坏文件不会毁掉正在编的电路。

文件按钮里是六个动作。打开、保存、另存为作用于整份电路；以选区导入、以选区导出只处理当前选区，导入时整批保持相对位置、落到视野中央；复制给 AI 会把整份电路写成一行一个元件的紧凑文本，方便粘进对话里让模型读电路。

左侧竖栏是工作区。选一个文件夹当工作区，栏里按目录结构列出里面的存档，双击打开，子文件夹可以逐层展开。换工作区之前会先问一句要不要丢弃未保存的改动，点头才往下走。当前文件有未保存的改动时，列表里那一行会亮起一个小圆点，写盘期间它还会呼吸。

在列表上点右键可以就地新建，菜单里是新建文件夹与新建文件两条，右键落在文件行上时还会多出一条删除。建在哪一层看右键落在哪一行：落在文件夹行上是建进它里面，落在文件行上或空白处是建在工作区根目录。定名字用的是就地冒出来的一行输入框，回车定下、Esc 或点到别处放弃；名字重复、带斜杠、没有写入权限这几种情况都不会把这一行收掉，只在它旁边写一句原因，改一个字就能重来。新建的文件一律带 `.lccas` 后缀，里面先写好一份空存档，双击打开就是一张空画布。

删除只针对文件，不动文件夹，删之前会问一句，问话里带着文件名和「删除后无法恢复」；这一条要是还留着没保存的改动，问话里会一并说明。删掉的如果是编辑器里正打开的那一个，文件绑定会一并解除，画面上的电路不动作，但它自此算作没有落处的改动，之后换工作区时仍会问一句要不要丢弃。

## 本地运行

双击 `index.html` 就能用，不需要装任何环境，也不需要本地服务器。脚本与样式都是相对路径引用的普通文件，直接读源码就能改。

两点限制需要知道。地址里带不带 `.html` 在本地控制不了：线上 `/editor` 是由服务器映射到 `editor.html` 的，本地只能按文件名打开。另外本地文件的读写走的是 `showSaveFilePicker` 这一组接口，目前只有 Chromium 系浏览器提供，其它浏览器下「打开」「保存」这几个入口会不可用，页面其余部分照常。

## 技术栈

原生 HTML、CSS、JavaScript，没有框架、没有运行时依赖，也没有打包器：源码就是浏览器直接执行的那一份文件。

渲染用 Canvas 2D，加上一层只装虚影的 SVG；动效走 `requestAnimationFrame`，动画状态用自己写的缓动函数推进。本地文件的读写走 File System Access API，用过的文件句柄记在 IndexedDB 里，下次打开文件框时从上次那个目录起步。字体是唯一的外部素材，取自小米发布的 MiSans，子集化后随页面一起走，不依赖任何字体 CDN。

发布时会用到 terser 做压缩，它只改 `dist` 里的副本，不进入页面运行，也不进入源码依赖。

## 代码约定

脚本之间靠全局作用域共享变量，因此两个页面里的加载顺序都不能随意调整。`util.js` 必须排在第一位，有两处硬依赖：`config.js` 在文件顶层就要调用 `hslToRgb` 把常态色、亮起色、选中色预先算成 RGB 端点，`state.js` 在文件顶层就要调用 `newEased` 建立几组缓动标量。这两处都在脚本刚加载时立即执行，工具函数一旦排在后面，整个页面会在加载阶段就中断，报出来的却是别的文件的行号。

同理，任何在文件顶层就被调用的函数，都必须来自比它更早加载的文件；只在函数体里调用的则不受这个限制。两个页面的加载顺序都写在 `index.html` 与 `editor.html` 的 `script` 标签处，打包脚本也直接读那里的顺序，不另抄一份。

状态变量集中在 `state.js`，可调参数集中在 `config.js`，主循环只负责按顺序调用各步。元件的形状只维护一份本地坐标点列，网格、激光、元件、面板都画在画布上，只有跟随指针的虚影走一层独立的 SVG，两边各自从同一份点列生成路径，形状不会漂移，首页演示电路里的元件与编辑器里的也是逐点相同的一份。

## 体积

线上要传的东西越小越好，`dist` 因此被压过。当前 7 个文件合计 227.9 KB，其中字体 125.5 KB、两个脚本 83.6 KB、样式表 6.7 KB、两个页面 12.1 KB。

字体这一项本来最大。官方 MiSans 的十个字重合计约 63 MB，每个字重带着约 2.9 万个字形，覆盖全部中日韩字符，而页面文案去重后只有几百个字。`tools/build-fonts.py` 扫描源码取出真正会用到的字，只留 400 与 700 两档，每档只保留约五百个字形：这两档原始文件合计 12.6 MB，子集化后是 125.5 KB。统计字符集时会先去掉注释，注释里的字永远不会画到屏幕上，算进去纯属白占体积，实测全站 1229 个字符里有 662 个只出现在注释中。

脚本这一项靠 terser。两个页面各自的脚本按页面里的加载顺序拼成一份，去掉注释与空白，再把函数名、变量名、参数名换成短名，从 356.4 KB 降到 83.6 KB。必须拼成一份才能改名：这些脚本原本靠顶层函数名互相调用，单个文件里改名会让跨文件调用全部对不上。对象属性名与 DOM 属性名一律不动，改了就和浏览器接口对不上。

把这些文件打成一个压缩包，再让页面自己解开，并不会更快。打包用 zip 的 Deflate，压不过服务器逐文件做的 Brotli：上传从 227.9 KB 降到 162.4 KB，但访客要从 155.6 KB 涨到 162.4 KB，还要等整包收完才能解出样式表与脚本。省上传和让访客少下在这里是互相冲突的，能同时改善两头的只有把内容真正变小。

## 发布

线上地址是 <https://laser.shayuyue.com> ，跑在 Cloudflare 的静态资源上，纯静态。上传用 Cloudflare 官方的 wrangler 命令行工具，本机已装 Node。以下命令都在项目根目录下执行，命令里的路径按本机位置写死，换一台机器跑时替换成你自己的项目目录。

改完源码之后先铺 `dist`：

```sh
cd "/Users/shayuyue/Desktop/Projects/激光逻辑门运算"
python3 tools/build-dist.py
```

这个脚本做四件事：把两个页面、`css/`、`js/` 重新复制进 `dist`（先整个删掉再复制，避免源码里已删除的文件继续留在发布目录）；按页面各自的加载顺序把脚本拼成一份，交给 terser 压缩改名，并把页面里那一串 `script` 标签换成一条；去掉两个页面与样式表里的注释和多余空白；清掉 macOS 自动生成的 `.DS_Store`。它同时会核对页面与样式表引用的每个文件是否都落在 `dist` 里，少一个就中止，不让残缺的产物传上线。压缩偶尔出问题时，加 `--no-minify` 可以铺一份未压缩的副本用来对照。

这一步需要 Node 与 npx，首次运行会联网取下 terser。页面本身不需要它，只有发布才用。

字体的构建与它并列，但不必每次跑。只有改动了页面文案之后才需要重跑一次，否则新写的字不在字体里，会回退到系统中文字体显示：

```sh
python3 tools/build-fonts.py
```

这一步依赖 fontTools 与 brotli，同样只在本地生成时用得到。

第一次部署前先登录一次：

```sh
npx wrangler login
```

这条命令会打开浏览器，跳到 Cloudflare 的授权页，登录账号后点一下 Allow 即可，终端随即打印登录成功。浏览器没有自动弹出来的话，把终端里那条 `https://dash.cloudflare.com/oauth2/auth?...` 整条复制到地址栏打开，效果一样。如果终端打印 `Timed out waiting for authorization code`，说明这次授权没有在时限内完成，那条链接已经失效，重跑一次换条新的即可。反复超时通常是三个原因：链接没打开、浏览器里没有登录 Cloudflare 账号、或者 `dash.cloudflare.com` 在当前网络下打不开。

如果本机根本打不开 `dash.cloudflare.com`，整个 OAuth 流程都走不通，可以改用 API Token 绕开浏览器授权。Token 在 Cloudflare 控制台的 API 令牌页面创建，模板选 `Edit Cloudflare Workers`，拿到后这样用：

```sh
export CLOUDFLARE_API_TOKEN="你的token"
npx wrangler deploy
```

带上这个环境变量跑部署，wrangler 就不再走登录流程。Token 是敏感凭证，只留在自己的终端里，不要写进仓库或文档。

平时更新只需一条命令：

```sh
npx wrangler deploy
```

它把 `dist` 传上去，并立即把线上切到新版本。登录凭证会过期，过期之后这条命令会报 `Not logged in`，重新跑一次 `npx wrangler login` 再重来即可，不需要改配置，也不需要重新绑定域名。判断依据看报错里那句话：说的是凭证过期，就是重新登录的事；报的是别的原因（网络不通、项目名对不上），那才是另外的问题。

部署成功后，终端会打印上传的文件数量、新的版本号，以及一个 `workers.dev` 地址。那个地址在国内打不开，属于域名层面的阻断，和部署成没成功无关；成功与否看文件数量和版本号即可，对外一律用自定义域名。

`wrangler.jsonc` 登记着四件事。`name` 决定更新哪个项目，写错或改动它会变成新建一个项目，原有项目上绑好的域名不会跟过去。`main` 指向 `worker.js`，也就是先于静态资源执行的那段拦截脚本，它在根目录、不在 `dist` 里，所以不需要同步进发布目录。`assets.directory` 指向 `dist`，所以只有 `dist` 里的内容会被上传，源码、文档、旧版本文件都不会出现在线上。`assets.html_handling` 取 `auto-trailing-slash`，`/editor` 直接取到 `editor.html`，`/editor.html` 则被 307 转回 `/editor`，所以线上编辑器的地址不带后缀。

线上对 `js/` 与 `css/` 的直接访问会被拦掉并返回 404，这是 `worker.js` 做的：它看浏览器自动附带的 `Sec-Fetch-Dest` 请求头，在地址栏直接回车时该值是 `document`，一律拒绝；页面内正常加载脚本和样式时分别是 `script` 和 `style`，照常放行。这只挡住闲逛式访问，项目本身是开源的，开发者工具里依然看得到脚本内容，命令行工具也不会带这个请求头。

部署完成后，顺手到项目页的「域名和路由」确认自定义域名还在，万一掉了，在那里重新添加一次即可。
